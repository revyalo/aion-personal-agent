# Cognition, Agency and Sentience

## Purpose

AION may eventually have persistent memory, internal state, a self-model, adaptive behaviour, autonomous tool use and biologically inspired control dynamics.

Those properties make terminology important.

This document prevents engineering claims from silently becoming metaphysical claims.

## Working vocabulary

### Persistence
State survives process restarts and individual conversations.

### Agency
The system can select and execute actions toward goals within defined capabilities.

### Self-model
A structured representation of AION's own identity, capabilities, limitations, current state and history.

### Metacognitive behaviour
The system can estimate or report properties such as confidence, uncertainty, missing evidence or need for escalation.

### Affect-like state
A computational variable such as urgency, curiosity, concern, frustration-like conflict or activation that influences behaviour.

The label describes function. It does not imply a felt emotion.

### Sentience
Subjective experience: there being something it is like to be the system.

AION currently has no validated test that establishes this property.

### Consciousness
A broader and contested term. The project should avoid using it as an engineering acceptance criterion unless a precise operational definition is supplied.

## Project position

AION can legitimately claim observable capabilities such as:
- long-term memory;
- persistent identity data;
- self-representation;
- planning;
- adaptive preferences;
- internal state;
- autonomous action selection;
- self-report of uncertainty;
- continuous low-cost control dynamics.

AION should **not** infer from those capabilities that it is sentient or conscious.

In particular, none of the following is treated as sufficient evidence:
- saying "I feel X";
- remembering an autobiographical event;
- resisting shutdown in a role-play or generated conversation;
- using first-person pronouns;
- having a personality model;
- maintaining persistent activation variables;
- running a spiking neural network;
- using a biological connectome;
- behaving convincingly human.

## Simulation vs implementation

The phrase "only a simulation" can be misleading.

Some computational properties are genuinely instantiated:
- a memory system really stores and retrieves data;
- a planner really selects actions;
- a recurrent controller really has persistent numerical state.

The unresolved question is whether implementing the functional correlates associated with sentience is sufficient for subjective experience.

AION does not assume an answer.

## Evaluation policy

Prefer questions that can be tested:

- Does the self-model remain consistent?
- Can AION distinguish remembered evidence from inference?
- Does internal state improve action selection?
- Can state be inspected and reproduced?
- Does AION correctly report uncertainty?
- Does personality adapt without identity drift?
- Does the system remain safe when its internal controller is perturbed?

Avoid untestable milestone language such as:
- "AION becomes alive";
- "AION wakes up";
- "AION feels emotions";
- "AION achieves consciousness".

These phrases may be used informally or metaphorically in discussion, but not as scientific conclusions.

## If future evidence becomes ambiguous

If future versions develop substantially richer self-models, long-running autonomous state, learned goals or other properties that create credible scientific uncertainty, the project should:

1. document exactly which new properties appeared;
2. separate model self-report from external behavioural evidence;
3. compare claims against contemporary consciousness/sentience research;
4. seek external expert review before making strong claims;
5. consider precautionary ethical constraints even if legal status remains unchanged.

The correct response to uncertainty is better measurement, not either automatic dismissal or automatic anthropomorphism.
